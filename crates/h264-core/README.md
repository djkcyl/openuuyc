# OpenUUYC H.264 software core

Platform-independent Rust implementation using FFmpeg's byte-plane, compact
coefficient and macroblock pipeline design. The implementation decodes progressive I/P pictures through CAVLC/CABAC,
including 420/444, multiple slices, weighted P, reference management and cropping.
Windows integration and parameter/cancellation/ownership regressions are implemented.
This is now the Windows client's only software video decoder. Representative playback is accepted; retained performance measurements do not
claim every input is faster than FFmpeg.
B frames, field/MBAFF and SP/SI are outside the verified UU sending contract; see
`docs/official-h264-encoder-contract.md`. They are explicitly rejected.

`picture` owns padded u8 420/444 frames, visible cropping, output packing and
unfiltered row borders. No B-picture motion field is retained with references. `bits`/`cabac` own bounded input and packed arithmetic
contexts. `dsp` provides common byte-plane prediction, motion, dequantization,
transforms and deblocking without C, external assembly or OS APIs. SSE2 covers
the active 8-bit DSP set. SSSE3 adds packed horizontal six-tap interpolation;
AVX2 adds paired 4x4 transforms, register-transposed 8x8 transforms and full-edge
deblocking and width-16 qpel after CPU/OS detection. Bounded coefficients use
packed i16 butterflies; larger values retain the exact wider arithmetic.
Macroblock residual batches dispatch once,
skip empty blocks and retain intra4/8 prediction dependencies. Integer motion
uses fixed-width copies, including short rows without source overreads.
CABAC uses Rust inline x86 arithmetic with bounded refill and checked block exits.
The portable paths remain available to other architectures. Two-row and 5x8
neighbour caches and per-slice scratch avoid frame-sized syntax objects.
Compile-time-validated immutable scan tables remove per-residual table walks;
inverse transforms clear the consumed scratch, including across mode changes.
P_SKIP has its own full-partition reconstruction path without residual setup.
Slice weights are prepared once and identity weights omitted; saturated MVD
contexts use i8 storage while actual motion vectors retain their full range.
Private checked macroblock/partition views eliminate repeated target-footprint
checks. Intra availability is resolved once per macroblock, not per pixel.
NV12 packing interleaves U/V rows with SIMD instead of per-sample Vec pushes.
CABAC 8x8 reconstruction counts retain one total while entropy neighbours keep
their replicated counts, enabling the DC-only path. Weighted integer motion
copies directly to its final clipped prediction. Deblocking receives a private
validated edge footprint and selects normal, all-strong or mixed kernels.

Ordinary application builds include this core and Rust DXVA11 unconditionally.
There is no video C ABI, FFmpeg video link or legacy feature switch. Unrelated
audio C/C++ dependencies have not yet been migrated.

Build with `cargo test --manifest-path src/decoder/h264-core/Cargo.toml`.
Tables are checked-in Rust arrays generated by
`python tools/generate-h264-rust-tables.py` from the pinned FFmpeg 8.0.3 source;
normal builds do not run Python, a C compiler or source downloads.
